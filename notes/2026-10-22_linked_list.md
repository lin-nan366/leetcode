## 876：为什么 5 个节点停在 3，6 个节点停在 4

```python
slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
```

条件要求 fast 和 fast.next 存在，允许 fast.next.next 是 None。

| 已完成的轮数 | slow | 5 个节点时的 fast | 6 个节点时的 fast |
| --- | --- | --- | --- |
| 0 | 1 | 1 | 1 |
| 1 | 2 | 3 | 3 |
| 2 | 3 | 5，next 为空，停止 | 5，next 是 6，继续 |
| 3 | 4 | 不执行第三轮 | None，停止 |

偶数长度有两个中点，题目要求第二个。返回节点 3 时显示 `[3, 4, 5]`，
是因为节点 3 后面仍连着 4、5，不代表循环额外移动了三步。

## 141 / 142：判断环与寻找入口

141 只需判断是否有环：slow 每轮一步，fast 每轮两步，移动后若指向同一节点就有环。
不能在首次移动前直接判断，因为初始化时两者都等于 head。

142 还需要找入口。第一次相遇只说明有环，相遇点不一定是入口。
让一个指针从 head 出发，另一个从相遇点出发，每轮都走一步，第二次相遇就在入口。

设头节点到入口距离为 a，环长为 L，第一次相遇时 slow 走了 s 步。
fast 走了 2s 步，多出的 s 步是完整的若干圈，因此 s = kL。
slow 在环里已经走了 s - a 步；再走 a 步后，在环里共走 s 步，恰好回到入口。
另一个指针从头走 a 步也到入口，所以两者会在那里相遇。

这里使用 `p is slow` 比较节点身份。两个不同节点即使 val 一样，也不能当作相遇。

## 反转后，从原来的 head 还能访问哪些节点

反转会真实修改 next，不会为输入节点创建副本。例如：

```text
原来：head -> 5 -> 4 -> 2 -> 1 -> None

从中点 2 开始反转后：
head  -> 5 -> 4 -> 2 -> None
head2 -> 1 ------> 2 -> None
```

两个路径中的 2 是同一个节点。原来的 2.next 已被改成 None，所以从 head
已经走不到原尾节点 1。变量保留的是节点引用，不会记住一份旧的连接结构。

## 143：交替连接，为什么用 head2.next

每轮先保存后续部分，再插入一个节点，最后移动指针：

```python
nxt = head.next
nxt2 = head2.next
head.next = head2
head2.next = nxt
head = nxt
head2 = nxt2
```

本写法两段共享中间节点，最后的共享节点已经连接好，不需要再次插入，
所以循环条件是 `while head2.next`。

例如 1 -> 2 -> 3 -> 4，完成一轮后已经是 1 -> 4 -> 2 -> 3。
此时 head 指向 2，head2 指向 3。如果再执行一轮，nxt 也是 3，
执行 head2.next = nxt 就会形成 3 -> 3 的自环。

这个停止条件与当前“共享中点”的写法配套；如果先彻底断开两段，合并条件需要相应调整。

## 234 / 2130：比较节点值，第二段处理完就停止

234 判断对称位置的 val 是否相同；2130 计算对称位置的 val 之和。
这里比较的是值，不能用节点身份代替值。

2130 保证偶数长度。对于 5 -> 4 -> 2 -> 1：

| 轮次 | head | head2 | 操作 |
| --- | --- | --- | --- |
| 1 | 5 | 1 | 计算 5 + 1 |
| 2 | 4 | 2 | 计算 4 + 2 |
| 准备进入第 3 轮 | 2 | None | 停止 |

head2 走到 None 时，所有孪生配对已经处理完，因此 `while head2` 就足够。
234 使用相同的比较终止方式；奇数长度时，中间节点会与自身比较一次，不影响结果。

234 若要恢复输入，必须固定保存反转后半段的头节点。比较中发现不同后先 break，
恢复连接后再返回 False；提前 return 会跳过恢复。

## 2816：最后的进位与结果入口

```python
while cur or carry:
    x = cur.val * 2 if cur else 0
    total = x + carry
    digit = total % 10
    carry = total // 10
```

cur 为空但 carry 非零时，还需要新建一位。以 9 为例，先写入 8、留下进位 1，
下一轮按 0 + 1 写入 1；生成 8 -> 1，再反转成 1 -> 8。
读取 cur.val 和推进 cur.next 前都要判断 cur 是否存在。

dummy 固定保存结果入口，tail 随追加移动。最后从 dummy.next 开始反转，
不能从已经移到最后一个节点的 tail 开始。

## 203 / 3217：删除后前驱不移动

```python
while cur.next:
    if 需要删除当前的后继节点:
        cur.next = cur.next.next
    else:
        cur = cur.next
```

cur 始终指向待检查节点的前驱。删除后留在原地，才能检查连续的目标节点。
cur 初始是 dummy，只在 cur.next 存在时向后移动，所以 cur 本身不会是 None。
空链表、删除头部、删除尾部、删除全部节点都可以统一处理。

3217 必须先在循环外创建集合：

```python
to_remove = set(nums)
```

再使用 `cur.next.val in to_remove`。在列表 nums 中查找，单次最坏 O(m)，
即使只遍历一次链表，总时间仍可能是 O(mn)。集合基于哈希表，成员查询平均 O(1)，
加上建立集合的开销，总时间降为平均 O(m + n)。

这题只关心值是否出现，顺序和出现次数都不影响删除，因此集合去重不会改变答案。
集合只建一次；放进 while 里面反复重建也会增加大量开销。
